# civ-tui 项目计划

> 目标：在终端中实现一个基本可玩的 Civilization 风格回合制策略游戏。

## 设计原则

1. **渐进式实现** -- 每个阶段交付可玩的版本，逐步增加深度
2. **TUI 优先** -- 所有功能设计都围绕终端界面的约束和优势
3. **简洁优于完整** -- 不追求还原完整 Civ，而是抓住核心乐趣
4. **可测试** -- 游戏逻辑与 TUI 分离，核心逻辑有测试覆盖

---

## 阶段一：修复与加固 (Foundation)

**目标**: 修复已知问题，建立工程基础，让现有功能正确运行。

### 1.1 Bug 修复
- [ ] 城墙 `DefBonus` 接入攻城计算 -- 在 `AttackCity()` 中读取城市建筑的防御加成
- [ ] 阵亡单位清理 -- 每回合结束时从切片中移除 HP<=0 的单位，或使用惰性删除+定期压缩
- [ ] 替换自实现 `itoa()` 为 `strconv.Itoa()`
- [ ] 城市名耗尽时使用 "City N" 备用命名

### 1.2 工程基础
- [ ] 添加 Makefile (`build`, `run`, `test`, `lint` targets)
- [ ] 核心逻辑单元测试 (战斗计算、城市产出、科技研究、地图生成)
- [ ] CI 配置 (GitHub Actions: build + test)

### 1.3 代码重构
- [ ] 将 AI 目标从硬编码 CivID 改为动态敌对关系查找
- [ ] 统一常量管理 (地图大小、视野距离、回合上限等提取为配置)

**里程碑**: 现有功能 bug-free，有基本测试覆盖，可通过 `make` 构建和测试。

---

## 阶段二：让科技有意义 (Tech Matters)

**目标**: 科技研究产生实际游戏效果，形成有意义的发展路线选择。

### 2.1 科技解锁体系
- [ ] 单位生产需要对应科技
  - 弓箭手 <- Archery
  - 枪兵 <- Bronze Working
  - 剑士 <- Iron Working
  - 骑兵 <- Horseback Riding
  - (战士、斥候、开拓者无需科技)
- [ ] 建筑建造需要对应科技
  - 谷仓 <- Pottery
  - 图书馆 <- Writing
  - 市场 <- Calendar (或新增 Currency 科技)
  - 城墙 <- Mining
  - 兵营 <- Bronze Working
- [ ] 科技菜单中显示解锁内容

### 2.2 AI 适配
- [ ] AI 科研优先级 (优先研究能解锁单位的科技，而非随机)
- [ ] AI 城市生产适配 (只生产已解锁的单位)

**里程碑**: 科技研究影响可生产单位和建筑，玩家需要规划发展路线。

---

## 阶段三：单位与战斗深化 (Combat Depth)

**目标**: 增加战斗策略层次。

### 3.1 单位治疗
- [ ] 驻扎在己方城市的单位每回合恢复 2 HP
- [ ] 不在城市中的单位跳过行动后恢复 1 HP
- [ ] 满 HP 单位不显示治疗信息

### 3.2 远程攻击
- [ ] 弓箭手支持远程攻击 (射程 2)
- [ ] 远程攻击不受反击伤害
- [ ] TUI 中支持选择远程攻击目标 (R 键进入射击模式)

### 3.3 地形战斗修正
- [ ] 丘陵防御加成 (+25% 防御)
- [ ] 森林防御加成 (+25% 防御)
- [ ] 河流渡河攻击减益 (未来河流实现后)

### 3.4 经验与晋升 (可选)
- [ ] 战斗获得经验值
- [ ] 升级选择加成 (攻击+1 / 防御+1 / HP+5)

**里程碑**: 战斗有更多策略考量 -- 地形利用、远近搭配、单位保护和治疗。

---

## 阶段四：经济与城市管理 (Economy)

**目标**: 增加经济决策深度。

### 4.1 维护费用
- [ ] 每个单位每回合消耗 1 金币维护费
- [ ] 每个建筑每回合消耗对应维护费
- [ ] 金币为负时：随机解散单位或拆除建筑

### 4.2 城市详情界面
- [ ] 专用城市管理界面 (按 Enter 在己方城市上打开)
- [ ] 显示：人口、各项产出、已建建筑、生产队列、增长进度
- [ ] 允许更换生产项目

### 4.3 地形改良 (简化版)
- [ ] 新增工人单位 (Worker)
- [ ] 工人可建造农场 (食物+1)、矿山 (生产力+1)
- [ ] 改良需要多回合完成
- [ ] 科技解锁：Agriculture -> 农场, Mining -> 矿山

**里程碑**: 有经济压力和决策，城市管理有实际意义。

---

## 阶段五：地图质量提升 (Better Maps)

**目标**: 生成更像样的地图，增加战略地理因素。

### 5.1 连贯地形生成
- [ ] 引入 Simplex/Perlin 噪声生成地形高度图
- [ ] 基于高度图分配地形类型 (低 -> 海洋, 中 -> 平地, 高 -> 山)
- [ ] 温度/湿度图决定草地/沙漠/苔原/森林分布
- [ ] 保证至少一块连贯大陆

### 5.2 战略地理
- [ ] 河流生成 (从山脉流向海洋)
- [ ] 河流提供食物加成 (+1 食物)
- [ ] 可配置地图大小 (小: 40x25, 中: 60x35, 大: 80x45)

### 5.3 小地图
- [ ] 信息面板底部显示缩略地图
- [ ] 标注己方城市和单位位置

**里程碑**: 地图有大陆、海洋、河流等地理特征，每局游戏地形有显著差异。

---

## 阶段六：外交与多文明 (Diplomacy)

**目标**: 支持更多文明和基本外交。

### 6.1 多文明支持
- [ ] 支持 3-6 个 AI 文明
- [ ] 每个文明独立配色
- [ ] 起始位置分散算法

### 6.2 基本外交
- [ ] 和平/战争状态
- [ ] 宣战/求和机制
- [ ] 外交界面 (D 键)

### 6.3 AI 外交决策
- [ ] 基于军力对比决定是否宣战
- [ ] 基于战损决定是否求和

**里程碑**: 游戏世界更丰富，有多方势力博弈。

---

## 阶段七：存档与配置 (Persistence)

**目标**: 游戏可以保存和继续。

### 7.1 存档系统
- [ ] JSON 序列化完整游戏状态
- [ ] 保存到 `~/.civ-tui/saves/`
- [ ] 加载存档恢复游戏
- [ ] 自动存档 (每 N 回合)

### 7.2 游戏配置
- [ ] 开始菜单 (新游戏 / 加载 / 退出)
- [ ] 游戏设置 (地图大小、AI 数量、难度)
- [ ] 难度影响 AI 产出加成

**里程碑**: 可以中断和继续游戏，有基本的游戏设置选项。

---

## 优先级总结

| 阶段 | 优先级 | 预估工作量 | 核心价值 |
|---|---|---|---|
| 一: 修复与加固 | **最高** | 小 | 正确性、可维护性 |
| 二: 科技效果 | **高** | 中 | 发展决策深度 |
| 三: 战斗深化 | **高** | 中 | 战斗策略性 |
| 四: 经济管理 | 中 | 中-大 | 经济决策深度 |
| 五: 地图质量 | 中 | 中 | 视觉与战略多样性 |
| 六: 外交多文明 | 低 | 大 | 世界丰富度 |
| 七: 存档配置 | 低 | 中 | 游戏体验完整性 |

> 阶段一到三完成后，游戏即可达到"基本可玩"的状态 -- 有意义的科技选择、有策略的战斗、有正确运行的游戏逻辑。后续阶段按需求和兴趣推进。
